Deadlock detection lab

Enter the currently allocated instances and each process’s outstanding resource requests. Unlike Banker’s safety test, detection evaluates a current state using outstanding requests.

Detection input

Comma-separated vectors and one row per process

What this test does

Detection algorithm

  1. Compute Available = Total − Allocation.
  2. Set Work to Available and mark processes with no allocation as finishable.
  3. Find an unfinished process whose Request ≤ Work.
  4. Assume it finishes, release its allocation into Work, and repeat.
  5. Any process still unfinished is part of the detected deadlocked set under this model.
Model assumption: one instance vector per resource type, with current outstanding requests provided explicitly. This is a detection exercise, not a prediction of future requests.

Mutual exclusion

Make resources sharable where the resource semantics permit it.

Hold and wait

Require all needed resources up front, or require processes to release held resources before requesting more.

No preemption

For suitable resource types, reclaim resources when a request cannot be fulfilled.

Circular wait

Impose a global ordering on resource types and require acquisition in that order.

Avoidance

Banker’s algorithm grants a request only if the resulting state remains safe.

Detection and recovery

Run detection periodically, then recover by terminating processes or preempting resources where safe and feasible.

Understand the rules

FCFS

Runs in arrival order. Simple, but long jobs can delay short jobs (convoy effect).

SJF

Chooses the shortest original burst among ready processes. The running job is not interrupted.

SRTF

Chooses the shortest remaining time. A newly arrived shorter job can preempt the current one.

Priority scheduling

This lab uses smaller numbers for higher priority. Starvation is possible without aging.

Round Robin

Each ready process receives up to one time quantum. Quantum size affects response and waiting.
